DBSP 教学 · Lesson 0006 · 约 25–30 分钟

Join 的三项增量：从双线性一步步展开

教程制作 · 李金懋（OceanBase）

本课处理双线性 join 的增量化：从新结果减旧结果展开出“变化×旧状态、旧状态×变化、变化×变化”三项。

依据：DBSP 论文关于线性、双线性、非线性算子以及递归电路的增量化定义与定理。

1. 核心问题：为什么 join 不是“只 join 两批变化”？

线性算子的完整增量等式是：(↑O)Δ=↑O。join 不同：一条新来的左表记录，不但可能匹配本批新右记录，还可能匹配数据库中早已存在的右记录。

推导目标：从 Lnew=Lold+ΔL 和 Rnew=Rold+ΔR 出发，逐行推出 join 的三项 delta，并解释为什么第三项不能漏。
对象含义
Lold, Rold本批事务开始前，左右输入的完整 Z-set
ΔL, ΔR本批左右输入变化，权重可正可负
Lnew, Rnew应用本批变化后的完整输入
Vold, Vnew旧、新 join 结果
ΔVVnew−Vold，下游真正需要应用的变化

2. 为什么 inner join 是双线性的？

本课公式中的 ⋈ 指 inner join。先明确下面公式中每个记号的含义：

记号含义
L、R左右两个输入 Z-set。它们都可以看成“记录 → 整数权重”的函数。
l、r分别取自左、右输入的一条具体记录。
L(l)、R(r)记录 l、r 在各自 Z-set 中的整数权重。
(L ⋈ R)(l,r)配对记录 (l,r) 在 join 输出 Z-set 中的权重。

如果 l 与 r 满足连接条件，它们会形成一条输出记录，其权重等于输入权重相乘；如果不满足连接条件，这个配对不会出现在输出中，权重为 0：

(L ⋈ R)(l,r) = L(l) × R(r) // l 与 r 满足连接条件 (L ⋈ R)(l,r) = 0 // l 与 r 不满足连接条件

例如 L(l)=2、R(r)=3，且二者满足连接条件，那么输出配对 (l,r) 的权重为 2×3=6。这里的括号表示“查询这条输出记录的权重”，不是再次执行一次 join。

现在固定右输入 R，把左输入 A+B 代入。对任意一对满足条件的记录 (l,r)：

((A + B) ⋈ R)(l,r) = (A(l) + B(l)) × R(r) = A(l) × R(r) + B(l) × R(r) = (A ⋈ R)(l,r) + (B ⋈ R)(l,r)

最后一个等式对每一对输出记录都成立，因此：

(A + B) ⋈ R = (A ⋈ R) + (B ⋈ R)

固定左输入时完全相同：

L ⋈ (C + D) = (L ⋈ C) + (L ⋈ D)

inner join 对左、右输入分别保持加法，因此称为双线性。当左右两边同时写成“旧状态 + 本批变化”时，两次使用分配律会产生四个组合。

3. 三项公式：每个等号依据是什么？

已知： Lnew = Lold + ΔL Rnew = Rold + ΔR Vold = Lold ⋈ Rold Vnew = Lnew ⋈ Rnew 定义输出变化： ΔV = Vnew − Vold 代入 Vnew 和 Vold： ΔV = (Lnew ⋈ Rnew) − (Lold ⋈ Rold) 代入两个新状态： = (Lold + ΔL) ⋈ (Rold + ΔR) − Lold ⋈ Rold 第一次使用双线性，对左输入展开： = Lold ⋈ (Rold + ΔR) + ΔL ⋈ (Rold + ΔR) − Lold ⋈ Rold 第二次使用双线性，对右输入展开： = Lold ⋈ Rold + Lold ⋈ ΔR + ΔL ⋈ Rold + ΔL ⋈ ΔR − Lold ⋈ Rold 消去一正一负的旧结果： ΔV = ΔL ⋈ Rold + Lold ⋈ ΔR + ΔL ⋈ ΔR

ΔL ⋈ Rold

本批左变化与事务前已经存在的右状态匹配。

Lold ⋈ ΔR

事务前已经存在的左状态与本批右变化匹配。

ΔL ⋈ ΔR

同一批事务内，左右两边的变化彼此匹配。

为什么没有旧×旧

它同时出现在新结果展开式和被减去的旧结果中，恰好抵消。

公式中的 Rold、Lold 必须是应用本批变化之前的状态。若改用 new 状态却仍加第三项，就会重复计数。

2.1 把单个时刻的公式写成流算子形式

令 a、b 分别是左右输入的变化流。先定义 inner join 对流的逐时刻作用：

(↑⋈)(x,y)[t] = x[t] ⋈ y[t]

对任意逻辑时刻 t，本批变化和本批开始前的状态分别是：

ΔLt = a[t] ΔRt = b[t] Lt−1 = z⁻¹(ℐ(a))[t] Rt−1 = z⁻¹(ℐ(b))[t]

因此，单个时刻的三项公式为：

ΔVt = ΔLt ⋈ Rt−1 + Lt−1 ⋈ ΔRt + ΔLt ⋈ ΔRt

把这个等式同时写在整条流上，就得到 inner join 的增量流算子：

(↑⋈)Δ(a,b) = (↑⋈)(a, z⁻¹(ℐ(b))) + (↑⋈)(z⁻¹(ℐ(a)), b) + (↑⋈)(a,b)
流公式中的一项在逻辑时刻 t 取值
(↑⋈)(a, z⁻¹(ℐ(b)))ΔLt ⋈ Rt−1
(↑⋈)(z⁻¹(ℐ(a)), b)Lt−1 ⋈ ΔRt
(↑⋈)(a,b)ΔLt ⋈ ΔRt
流公式不是另一套规则。它只是把每个逻辑时刻都成立的三项等式，统一写成一个从两条输入变化流到输出变化流的算子等式。

4. 删除：三项如何得到正确结果？

先澄清“权重”的对象：Z-set 的权重属于一条完整记录，不是属于连接键。两条记录即使 customer_id 相同，只要其他字段不同，就是两个不同的 Z-set 元素，不能合并成同一条记录计数。只有完整字段都相同的记录，才会合并为同一个元素并累加权重。

下面不用重复记录，而是使用多条连接键相同、内容不同的记录，观察同一批两侧删除时三项如何得到正确结果。

左侧有三条不同的订单，右侧有两条不同的客户标签；它们的连接键都是 customer_id=7：

左侧完整记录右侧完整记录
l1=(order_id=O1, customer_id=7, amount=50)r1=(customer_id=7, tag=VIP)
l2=(order_id=O2, customer_id=7, amount=80)r2=(customer_id=7, tag=NEW)
l3=(order_id=O3, customer_id=7, amount=120)—
Lold = {l1↦1, l2↦1, l3↦1} Rold = {r1↦1, r2↦1}

inner join 会产生六条不同的配对记录，每条权重都是 1：

Vold = { (l1,r1)↦1, (l1,r2)↦1, (l2,r1)↦1, (l2,r2)↦1, (l3,r1)↦1, (l3,r2)↦1 }

本批同时删除订单 l3 和标签 r2：

ΔL = {l3↦−1} ΔR = {r2↦−1}

删除后只剩 l1、l2 与 r1 的两个配对，因此应撤回以下四条旧结果：

ΔV = { (l3,r1)↦−1, (l3,r2)↦−1, (l1,r2)↦−1, (l2,r2)↦−1 }

三项公式分别产生：

项产生的输出变化
ΔL ⋈ Rold{(l3,r1)↦−1, (l3,r2)↦−1}
Lold ⋈ ΔR{(l1,r2)↦−1, (l2,r2)↦−1, (l3,r2)↦−1}
ΔL ⋈ ΔR{(l3,r2)↦+1}

配对记录 (l3,r2) 在前两项中各被撤回一次，合计权重为 −2；第三项加回 +1，使它最终只撤回一次。其他三条配对记录各保持 −1。

这里没有把“连接键相同的行”合并计数。三项公式始终在完整输出记录上累加权重；只有同一个完整配对 (l3,r2) 在多项中重复出现时，它的权重才会相加。

5. 拓展：LEFT JOIN 为什么不能直接使用三项公式？

LEFT JOIN 不具有 inner join 的双线性性质。固定右输入时仍可对左保持加法；反之通常不行——“右侧是否存在匹配”依赖右侧合并后的整体状态，不能分别计算再相加。

例如左侧只有记录 l，右侧输入 R1 为空，R2 中有一条与 l 匹配的记录 r：

L LEFT JOIN (R1 + R2) = {(l,r) ↦ 1} (L LEFT JOIN R1) + (L LEFT JOIN R2) = {(l,NULL) ↦ 1} + {(l,r) ↦ 1}

左右结果不同，所以不能把 inner join 的三项双线性增量公式直接用于整个 LEFT JOIN。LEFT JOIN 通常需要拆成 inner join 与“未匹配左记录补 NULL”的部分；后者需要维护匹配是否存在的状态。

6. 小结

  1. join 对左右输入分别线性，所以是双线性算子。
  2. 从新结果减旧结果完整展开后，旧×旧抵消，剩下三项。
  3. 第三项负责同批变化之间的匹配，也负责双边删除时的容斥修正。
  4. 实现需要保留事务开始前的 Lold/Rold 状态；计算完 delta 后再更新状态。
必须能脱稿写出： Δ(L ⋈ R) = ΔL ⋈ Rold + Lold ⋈ ΔR + ΔL ⋈ ΔR
