DBSP 教学 · Lesson 0011 · 约 25–30 分钟

递归、不动点与 Frontier：变化如何穿过反馈环

教程制作 · 李金懋（OceanBase）

本课把递归查询表示为带 Delay 的反馈电路，补上 δ₀/∫ 作为反馈环的入口与出口，并通过可达性例子说明不动点、frontier、Cycle Rule 和嵌套流。

依据：DBSP 论文关于线性、双线性、非线性算子以及递归电路的增量化定义与定理。

1. 核心问题：递归查询为什么是“带反馈的电路”？

非递归查询从输入一路向前计算；递归查询的本轮结果会成为下一轮输入。以图可达性为例：

Reach(x,y) :- Edge(x,y). Reach(x,z) :- Reach(x,y), Edge(y,z).

第一条规则给出一步可达；第二条规则不断把已有路径向后延长。只有没有新路径产生时才停止。

推导目标：理解不动点、δ₀/∫ 边界、反馈延迟和 frontier（本轮新结果）如何配合；不把递归误解成“一次 join”。

2. 从规则写成不动点方程

令 E 是边关系，R 是当前已知可达关系。定义一步函数：

F(R) = E ∪ (R ⋈ E)

这里 join 条件是 R.to = E.from，输出 (R.from,E.to)。最终 Reach 是满足下式的最小结果：

R* = F(R*) = E ∪ (R* ⋈ E)

这叫最小不动点。计算方式从空集开始反复应用 F：

R₀ = ∅ R₁ = F(R₀) R₂ = F(R₁) ... 直到 Rₖ₊₁ = Rₖ
“最小”意味着只包含由规则有限次推出的事实，不凭空加入其他满足方程的记录。

3. 为什么朴素迭代会重复做大量工作？

每一轮都用完整 Ri 再 join 一次 E，会反复推导早已知道的路径。semi-naive/frontier 思路只让上一轮新增路径继续传播：

Known₀ = distinct(E) Frontier₀ = Known₀ 每轮： Candidatesᵢ = Frontierᵢ ⋈ E Knownᵢ₊₁ = distinct(Knownᵢ + Candidatesᵢ) Frontierᵢ₊₁ = Knownᵢ₊₁ − Knownᵢ Frontier 为空时停止。
为什么不能写 distinct(Candidates−Known)？同一事实在 Candidates 权重 2、Known 权重 1 时，相减再 distinct 会误判为新事实。稳健做法：先形成新完整 Known，再取 Knownnew−Knownold。

这和 IVM 的核心直觉一致：不要让完整历史反复穿过算子，只处理尚未传播的变化。

4. 新增一条边，逐轮产生新路径

事务前边和旧可达闭包：

Eold = {A→B, B→C, D→E} Rold = {A→B, B→C, A→C, D→E}

本批新增边：

ΔE = {C→D}

这条边先作为新的一步路径进入 frontier，然后与旧路径和旧边继续组合：

轮次frontier来源
0C→D本批新增边本身
1A→D, B→D, C→EA/B 原来能到 C；C→D 再接 D→E
2A→E, B→E新得到 A/B→D，再接旧边 D→E
3∅没有尚未见过的新路径，停止
ΔReach = {C→D, A→D, B→D, C→E, A→E, B→E}

最终将 ΔReach 加到旧闭包，等于在新图上重新计算完整可达关系；但执行只传播由新边触发的 frontier。

为什么表中轮次可能因实现调度略有合并？

有的执行器会在一个内部批次中做更多组合，使 C→E 与 A→D 等在同一轮或相邻轮出现。关键不在轮号，而在每个新事实只作为 frontier 继续传播，直到没有新事实。

5. 电路里的反馈为什么需要 z⁻¹？

┌───────────────┐ base E ──→ (+) ──→ recursive body ──→ Reach ▲ │ └── z⁻¹ ──────┘

若输出在同一个逻辑时刻无延迟地立刻反馈到输入，就会形成“当前值依赖当前值”的组合环，执行顺序和语义都不清楚。z⁻¹ 把反馈推迟一个逻辑步：

  • 本轮读取上一轮已知状态；
  • 本轮产生新的 frontier；
  • 下一轮再消费这些新结果。
delay 不是为了故意变慢，而是给反馈环建立清晰的逻辑时间边界。

6. δ₀ 与 ∫：反馈环的入口与出口

第 4 节只画了环内的 z⁻¹。论文 §5 还引入一对“流的边界算子”，把一次固定点计算嵌进更大的（事务）时间轴：

算子方向作用
δ₀标量 → 流入口：把输入关系嵌成只在内部时刻 0 非零的流，δ₀(v)=[v, 0, 0, …]
∫流 → 标量出口：对“几乎处处为零”的变化流求和，取出固定点终值
ℐ / 𝒟流 ↔ 流环内不定积分 / 微分；与出口上的定积分 ∫ 角色不同
绝缘约定：良构电路用 δ₀ … ∫ 包住一段独立内部时钟，避免内外时间轴混用（论文 Proposition 5.3 的 zero-preservation）。

5.1 论文中的递归电路（朴素形态）

把非递归体 R 提升为流算子后，按 §5.1 接成反馈环：

ASCII 对照（课内原图）
I ──→ δ₀ ──→ ℐ ──→ ↑R ──→ ↑distinct ──→ 𝒟 ──→ ∫ ──→ O ▲ │ └─── z⁻¹ ◄───┘ （o：↑distinct 的输出流，逐轮近似）

逐节点回指（把图上的每一块钉回本课已讲概念）：

节点在环中做什么回指
δ₀把本批输入关系 I 送入内部迭代时钟本节入口
ℐ把 δ₀(I) 积成内部时钟上的常量 I 流，送入 ↑R 左输入（论文：左输入是常量 I 流）第 0003 课
↑R对当前近似做一步规则体（join/union 等）§1 的 F / §0 规则
↑distinctZ-set 上的集合语义，合并多重推导第 7 课 distinct 状态
𝒟本轮近似 − 上轮近似 = 本轮新事实§2–3 的 frontier
z⁻¹把本轮结果推迟到下一内部时刻再读§4
∫累加各轮 𝒟 输出，得到固定点 O本节出口
读图口诀：δ₀ 开门开内部时钟 → 环内用 z⁻¹ 一轮轮逼近 → 𝒟 吐出 frontier → ∫ 关门取出终值。

当某轮 𝒟 输出为空（frontier 空），内部流此后全零，∫ 已拿到稳定 O。这正是有限图可达性例子的停机画面；无界域上仍不保证终止。

7. Cycle Rule 应该怎样理解？

论文的完整公式保留了外部输入、固定点变量和反馈 delay：

(λs. fix α. T(s, z⁻¹(α)))Δ = λs. fix α. TΔ(s, z⁻¹(α))
符号完整含义
s递归电路的外部输入流
α固定点反馈流变量
T同时读取外部输入与上一轮反馈的递归体流算子
TΔ流算子 T 的增量算子；T 已经是流算子，因此这里不需要再写 lift
z⁻¹(α)将反馈流 α 延迟一个内部逻辑时间步

这条式子说的是：在满足论文良构/因果条件的 DBSP 电路中，增量化可以穿过这个特定反馈结构；它不是任意程序语言递归函数的无条件代数等式。

因果 / 严格因果：
  • 因果：时刻 t 输出只依赖 ≤ t 的输入——不偷看未来；lift 与 z⁻¹ 皆因果。
  • 严格因果：只依赖 < t 的输入——本轮不看本轮；z⁻¹ 满足，故 fix α. T(s, z⁻¹(α)) 有唯一解。
  • Cycle Rule 只适用于已带严格因果反馈的结构；即时环不在范围内。

含义是：把递归体中的 filter、join、distinct 等节点按各自的局部规则增量化，再保留反馈结构，便可让 frontier 在增量递归体中循环。

semi-naïve 钩子：论文 §5.1 指出，§5 朴素环（ℐ/𝒟 夹住 ↑R）经 Cycle Rule 改写后，等价于把环体直接换成增量算子：
I ──→ δ₀ ──→ (↑R)Δ ──→ (↑distinct)Δ ──→ ∫ ──→ O ▲ │ └──────── z⁻¹ ────────────┘

这正是 semi-naïve evaluation：每一内部时刻只让“新推导”进入下一轮，而不是整表重 join。Cycle Rule 不是额外发明的优化口号，而是 semi-naïve 正确性的代数来源。

术语对齐 · frontier：本课的 frontier（§3–4「上一轮新增且尚待传播的事实」）＝朴素环 𝒟 的输出，＝semi-naïve 环增量体 (↑R)Δ / (↑distinct)Δ 吐出的变化；frontier 空 ⇔ 迭代可停。
不要过度外推：这不是对任意数学函数、任意无延迟循环都无条件成立的口号。论文中的 cycle rule 依赖 DBSP 对电路、时间、可因果执行和反馈结构的定义。实际推导必须满足相应良构条件。

对可达性，递归体里的 join 仍使用双线性增量公式，distinct 仍需要 multiplicity 状态；递归不会取消这些局部规则。

8. 完整增量递归为什么需要 nested streams？

普通 fixed-point 计算内部本来就有一条“每轮新增事实”的变化流；当数据库又按事务持续变化时，会出现两层逻辑时间：

外层时间 t：输入事务/批次 0,1,2,… 内层时间 i：某个事务内的 fixed-point iteration 0,1,2,…

论文用 nested streams（嵌套流）表达这二维结构：外层流的每个元素，本身是一条内部迭代流。增量递归不是只保存最终闭包；它要能够调整由旧输入产生的 fixed-point 迭代历史，使外层输入变化沿内层反馈传播。

终止边界：这个有限图可达性例子会在 frontier 为空时停止；一般 DBSP 递归在无界域上不保证终止。运行时并不承诺所有循环都会结束，只保证在计算终止时结果满足语义。

9. 删除为什么比插入更难直觉化？

插入一条边只会增加可达路径；删除一条边可能让某条路径消失，也可能因为还有其他替代路径而继续存在。例如 A→C 同时可由直接边和 A→B→C 推出，删除其中一个证明不能立即删除结果。

Z-set multiplicity 可以把不同推导贡献计数；distinct/阈值状态再判断结果是否仍然存在。其处理过程是：

删除边 → 产生负的路径贡献 多个证明的正负权重合并 只有最终存在性从正数降到 0，才撤回 Reach 记录
这正是“递归 + join + distinct 状态”组合起来的地方。不要为删除另造一套完全独立的语义。

10. 小结

  1. 递归查询是求最小不动点，电路上表现为带 z⁻¹ 的反馈。
  2. δ₀ / ∫ 是反馈环的入口与出口：打开内部迭代时钟，并在 frontier 耗尽后取出固定点。
  3. z⁻¹ 提供严格因果，使 fix 有唯一可执行解；因果/严格因果是 Cycle Rule 的前提，不是装饰。
  4. frontier（= 环上 𝒟 / 增量体输出的新事实）只传播尚未见过的变化；semi-naïve 是 Cycle Rule 的直接推论。
  5. 完整增量递归还要 nested streams 处理“事务 × 迭代”二维时间；删除仍走 multiplicity + distinct 状态，不另起炉灶。
