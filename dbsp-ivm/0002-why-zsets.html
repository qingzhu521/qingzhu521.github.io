为什么普通集合不够用：Z-set 用「整数权重」统一数据与变化

教程制作 · 李金懋（OceanBase）

本课为数据库快照和变化提供统一的数据类型：Z-set。整数权重使插入、删除、重复记录和状态相加都能使用同一套代数运算。

依据： DBSP §4.1 ℤ-sets as an abelian group · 论文例子：{joe ↦ 1, anne ↦ −1} · arXiv:2203.16684

1. 普通集合为什么不够用？

看一张会员表（先当集合）：

S = { alice, bob }

插入还好说

S ∪ {carol} = {alice, bob, carol}

并集在集合世界里封闭。

删除也「好像」可以

S \ {bob} = {alice}

集合差有定义——但前提是你知道「差」是特殊运算，不是「加一个负的 bob」。

真正麻烦的三件事

  1. 变化与快照类型不统一。
    快照是集合；变化却需要记录「删了谁」。若变化也想用同一种对象表示，集合做不到「带负号的元素」。
  2. 没有逆元，就不好谈「群上的积分/微分」。
    快照与变化的累加 / 差分，数学上要在交换群上才干净：每个元素 x 都有 −x，且 x + (−x) = 0。
  3. 多重出现与去重语义纠缠。
    SQL 的 UNION ALL vs UNION、COUNT(*) vs COUNT(DISTINCT)，集合一层表示力不够，需要「计数」。
人话总结：增量维护既要「加一行」，也要「减一行」，还要把很多次变化加在一起。 集合只会「在不在」，不会「加多少 / 减多少」。

2. Z-set：给每个值挂一个整数权重

论文定义（人话版）：

Z-set = 从「可能出现的值」到「整数」的映射，且只有有限个值权重非 0。
写作 {值 ↦ 权重, ...}。权重也叫 multiplicity。
对象集合写法Z-set 写法含义
快照 {alice, bob} {alice ↦ 1, bob ↦ 1} 每人都「出现 1 次」
插入 carol ∪ {carol} {carol ↦ 1} 权重 +1
删除 bob \ {bob} {bob ↦ −1} 在变化流中，权重 −1 表示删除 / 撤销一次
混合变化 （难写） {carol ↦ 1, bob ↦ −1} 同一次事务里又插又删

论文里的玩具例子（字符串上的 Z-set）：

R = { joe ↦ 1, anne ↦ −1 } 读法： R[joe] = 1 → joe 以权重 +1 出现 R[anne] = −1 → anne 以权重 −1 出现（像一条“删除 anne”的记录） 其它名字权重都是 0，视作不存在

出处：DBSP §4.1 对 ℤ[A] 与 multiplicity 的定义与例子。

三种基本形态

像集合（set-like）

所有非零权重都是 +1。
例：{a↦1, b↦1}

像多重集 / bag

权重都是 ≥ 0 的整数。
例：{a↦3} 表示 a 出现 3 次（UNION ALL 场景）。

像变化（change / delta）

权重可正可负。
例：{a↦1, b↦−2}：插入一个 a，删掉两个 b。

统一表示：快照、变化、中间结果，全是同一种东西——Z-set。 “累加变化得到快照”现在有了统一类型。

3. 运算：按「每个值」把权重相加

Z-set 的加法非常机械——对每个值，权重分别相加：

({alice ↦ 1, bob ↦ 1}) + ({bob ↦ −1, carol ↦ 1}) = {alice ↦ 1, bob ↦ 0, carol ↦ 1} = {alice ↦ 1, carol ↦ 1} ← 权重 0 的直接丢掉

减法 = 加「全部取负」：

X − Y := X + (−Y) −{bob ↦ 1} = {bob ↦ −1}

零元：所有权重都是 0 的空映射，记作 0 或 ∅。

用一组时间步重算快照

t变化 Δ（Z-set）快照 = 到目前为止的 ΣΔ
0 ∅ ∅
1 {A:10 ↦ 1, B:20 ↦ 1} {A:10↦1, B:20↦1}
2 {C:30 ↦ 1} {A:10↦1, B:20↦1, C:30↦1}
3 {B:20 ↦ −1} {A:10↦1, C:30↦1}
4 {A:10 ↦ −1} + {A:25 ↦ 1} {A:25↦1, C:30↦1}

注意：这里把整行 (id, amount) 当作 Z-set 的「值」。更新 A 金额，必须拆成「删旧行 + 插新行」，因为旧行和新行是两个不同的值。

4. 「交换群」人话版

先用一句话记住什么是群（group）： 一个集合配上一套二元运算，且满足几条公理——运算后还在集合里、可以结合、有单位元、每个元素有逆元。 多一条「运算可交换」就是交换群 / 阿贝尔群（abelian group）。

公理抽象说法Z-set 上长什么样
封闭性 X、Y 在集合里 → X+Y 也在 两个 Z-set 逐 key 加权重，还是 Z-set
结合律 (X+Y)+Z = X+(Y+Z) 多次事务累加与加括号顺序无关
单位元 存在 0，X+0 = X 空映射 ∅（所有权重为 0）
逆元 每个 X 有 −X，X+(−X)=0 权重全部取反：删 = 加负权重
交换律
（交换群多这一条）		 X+Y = Y+X 先插后删 vs 先删后插，最终权重一样则结果一样

论文说 ℤ[A]（值域为 A 的 Z-set）构成交换群。可以压成三句：

  1. 可加（封闭 + 结合）：两个 Z-set 相加，还是 Z-set；连加与括号无关。
  2. 有零、有逆：空是 0；任意 X 都有 −X，且 X + (−X) = 0。
  3. 可交换：X + Y = Y + X。
为什么重要？因为积分 ℐ、微分 𝒟 是建在「流的值属于某个群」之上的——要会加、会减、有零。 普通集合缺少统一逆元；Z-set 使快照与变化的互转建立在同一种可加减的数据类型上。

5. distinct：把“有几份”变成“是否存在”

到这里，Z-set 已经能表示重复和删除：一条记录的权重可以是 2、1、0 或负数。 但有些 SQL 操作并不关心“有几份”，只关心“是否至少有一份”。DISTINCT 做的就是这件事。

先看一个重复记录

设输入 Z-set 为：

m = {a↦2, b↦1}

它表示记录 a 有两份，记录 b 有一份。 对 SELECT DISTINCT ... 而言，两份 a 仍只应显示一次：

distinct(m) = {a↦1, b↦1}
输入中记录 x 的权重distinct 后 x 的权重读法
00x 不存在
11x 存在一次
2、3、…1x 虽有重复，但结果只保留一次

所以可以把它记成：正权重变成 1；非正权重变成 0。

distinct(m)[x] = 1 若 m[x] > 0 0 若 m[x] ≤ 0

删除时，为什么不能过早忘掉计数？

从两份 a 开始：

当前 m = {a↦2} distinct(m) = {a↦1}

现在删除一份 a，变化是 δ={a↦−1}。Z-set 的加法先更新计数：

m + δ = {a↦1} distinct(m + δ) = {a↦1}

虽然底层少了一份 a，但结果中 a 仍然存在，所以 DISTINCT 的输出不变。 只有再删除一份、使权重从 1 变成 0 时，输出才需要撤回 a。

这里 Z-set 加法和 distinct 的分工很清楚： 加法负责保留并更新精确计数；distinct 读取更新后的计数，再回答“记录是否存在”。 distinct 本身是作用在 Z-set 上的算子，输入和输出都是 Z-set。

为什么不能把 distinct 分到加法两边？

取两份来源各自提供一条相同记录：

X = {a↦1}, Y = {a↦1} X + Y = {a↦2}

正确做法是先合并计数，再去重：

distinct(X + Y) = distinct({a↦2}) = {a↦1}

若分别去重后再相加，仍会得到两份：

distinct(X) + distinct(Y) = {a↦1} + {a↦1} = {a↦2}

因此 distinct(X + Y) 不等于 distinct(X) + distinct(Y)。 换句话说，distinct 不能像普通 Z-set 加法那样拆开计算：它必须看到合并后的总计数。

SQL 中何时会用到它？

SQLZ-set 直觉原因
UNION ALLX + Y保留两边带来的重复记录
UNIONdistinct(X + Y)合并后去重
EXCEPTdistinct(X − Y)先相减，再只保留仍存在的记录
一句话小结：Z-set 用整数权重保存“有几份”；distinct 把这个计数压成“是否存在”。 它必须观察合并后的计数，因此不满足 distinct(X+Y)=distinct(X)+distinct(Y)。

出处：DBSP Definition 4.3（distinct）；Table 1 中 UNION / EXCEPT 的翻译。

6. 快照与变化的统一表示

现在可以更准确地说：

  • 流里每个时刻的值，类型是 Z-set（不是裸集合）
  • ℐ 对每个 key 做权重的前缀和；𝒟 对每个 key 做权重的相邻差
  • amount=25 是行内容；权重 −1/+1 是增删次数，两者不是一回事
  • set-like 快照通常只有 0/1 权重；bag-like 快照可以有重复计数；负权重主要出现在变化和中间抵消过程中
set-like 快照：每个 key 的权重为 0 或 +1 bag-like 快照：每个 key 的权重为非负整数 变化：权重可正可负；负权重用于撤销旧行或抵消已有权重 快照 + 变化 → 新快照：逐 key 加权重

快照更新在 Z-set 中写为：Xt = Xt−1 + dt。积分 ℐ 把一串 dt 累加成 Xt，微分 𝒟 则把相邻 Xt 相减。

7. 小结

  • Z-set：值 → 整数权重的有限映射
  • 正权重偏插入 / 存在；负权重偏删除
  • 加法 = 逐值加权重；权重 0 = 不存在
  • 快照与变化同一类型 → 才能干净地做 ℐ / 𝒟 与自动增量化
  • distinct 把计数压回集合语义；它是非线性算子
