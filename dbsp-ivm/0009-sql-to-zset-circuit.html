SQL 快照查询到有类型的 Z-set 电路

教程制作 · 李金懋（OceanBase）

本课固定一条 SQL 和一张输入快照，把查询逐层翻译为 filter、project、grouping、每组 SUM 与结果行构造组成的快照电路。

依据：DBSP 论文 §4 的关系算子到 Z-set 算子翻译，以及 §7.2–§7.4 对 aggregation、indexed Z-set、grouping 与 GROUP BY-AGGREGATE 的扩展。

1. 问题：SQL 文本怎样变成可执行的电路？

数据库可以直接解释 SQL 文本，但 DBSP 的代数变换需要另一种输入：节点是有明确语义的算子，边上是有明确类型的值。下面这条查询同时包含行过滤、列投影、分组和聚合，编译器必须先把这些责任拆开。

SELECT region, SUM(amount) AS total FROM orders WHERE amount >= 20 GROUP BY region;

本课只讨论这条查询对一张完整快照的计算结果，不引入变化流或跨批状态。

2. 先按 SQL 语义直接算一次

输入记录类型为 Order = (OrderId, Region, Amount)。固定快照 X ∈ ℤ[Order] 如下；权重属于完整订单记录。

记录order_idregionamount权重
AAEast101
BBEast201
CCWest301
DDEast251

WHERE 去掉 A；East 组留下 B20、D25，West 组留下 C30。因此直接 SQL 结果是：

East: 20 + 25 = 45 West: 30 = 30 V = {(East,45)↦1, (West,30)↦1}

后面的电路翻译必须得到完全相同的 V ∈ ℤ[Result]，其中 Result = (Region, Total)。

3. 定义电路中的类型与算子

先定义投影后的记录类型 Pair = (Region, Amount)。四层算子的类型是：

层快照算子类型作用
过滤F : ℤ[Order] → ℤ[Order]只保留 amount ≥ 20 的订单，保留记录权重
投影P : ℤ[Order] → ℤ[Pair]把订单映射为 (region, amount)，相同输出的权重相加
分组Gp : ℤ[Pair] → ℤ[Pair][Region]按 p(region,amount)=region 建立索引
分组聚合Agga : ℤ[Pair][Region] → ℤ[Result]对每个 grouping 求和并构造结果行

ℤ[Pair][Region] 是 indexed Z-set：它可看作从每个 Region 键到一个 ℤ[Pair] 子 Z-set 的有限映射。这里的 “East 桶” 不是无类型容器，而是 East 键对应的完整子 Z-set。

Q : ℤ[Order] → ℤ[Result] Q = Agga ∘ Gp ∘ P ∘ F

等式依据是 SQL 的逻辑处理顺序：先 WHERE，再准备分组所需字段，再 GROUP BY，最后为各组产生聚合结果。

4. SQL 集合算子的 DBSP 实现速查（论文 Table 1）

上一节为本课的 GROUP BY 查询定义了 F、P、Gp 与 Agga。更一般地，论文 §4.2 的 Table 1 给出关系集合算子到 Z-set 电路的翻译：假定全局输入是集合（每个元素权重为 0 或 1），电路输出也必须是集合。

SQL / 关系算子SQL 语义（集合）DBSP 实现（Z-set 电路）
selection σPSELECT * FROM R WHERE PfilterP(R)
projection πASELECT DISTINCT A FROM Rdistinct(projectA(R))
unionR UNION Sdistinct(R + S)
intersectionR INTERSECT SR ⋈ S（对全部公共列等值连接）
differenceR EXCEPT Sdistinct(R − S)
equi-join ⋈R JOIN S ON R.c1 = S.c2joinc1=c2(R, S)
distinctSELECT DISTINCT * FROM Rdistinct(R)

出处：DBSP 论文 Table 1（Implementation of SQL relational set operators in DBSP）及 §4.2 正文；输入 R、S 视为集合，输出亦为集合。

规则一：集合语义算子末尾挂 distinct。 投影、并、差可能把权重加到大于 1；末尾 distinct 把正权重压回 1、非正压回 0。它不是免费节点：需对照旧权重判断存在性边界（第 7 课的 H），编译器会合并相邻 distinct。
规则二：intersection 是 equi-join 的特例；difference 用权重取负。
  • R INTERSECT S：对全部公共列等值连接（R ⋈ S）；集合输入下权重 ≤ 1，不必再挂 distinct。
  • R EXCEPT S：S 权重取负与 R 相加，再 distinct 保留权重 > 0 者。
// 论文 §4.2 给出的典型等式 R ∪ S = distinct(R + S) R \ S = distinct(R − S) (R × S)((x,y)) = R[x] × S[y] // 笛卡尔积按完整配对 (x,y) 相乘权重；等值连接是其加谓词的特例

与本课 bag 示例的关系：Table 1 约定的是集合语义，故投影／并／差末尾有 distinct。本课固定查询保留 SQL bag 语义（见第 8 节），电路是 Q = Agga ∘ Gp ∘ P ∘ F，不在 P 后插入 distinct；两种约定不矛盾，差别只在是否要求输出为集合。

5. 展开分组聚合，不使用黑盒宏

5.1 每个子 Z-set 上的 SUM

对任意组内子 Z-set s ∈ ℤ[Pair]，定义：

aSUM(s) = Σ amount(x) × s[x] // 依据：论文 §7.2 的加权 SUM 定义

s[x] 是完整 Pair 记录 x 的整数权重。若要判断一个组是否有输入记录，还可计算 aCOUNT(s)=Σ s[x]。当前快照中所有组都非空，SUM 手算已足够；COUNT 在组可能消失时用于区分“空组”和“总和恰为 0 的非空组”。

5.2 makeset 与每组函数 a

aSUM 产生标量，而查询输出必须是 Z-set 关系。论文用 makeset 把一个值包装成权重为 1 的 singleton Z-set：

makeset : Result → ℤ[Result] makeset(v) = {v↦1} // 依据：论文 §7.2 的 makeset 定义 a(k,s) = ∅ 若 aCOUNT(s)=0 makeset((k, aSUM(s))) 若 aCOUNT(s)>0 // 依据：SQL GROUP BY 只为非空组产生结果行；当前输入是非负 bag 快照

5.3 Agga 合并各组结果

对 indexed Z-set g ∈ ℤ[Pair][Region]，论文 §7.4 的 nested relation aggregation 对每个 grouping 独立调用 a，再把结果相加：

Agga(g) = Σk∈Region a(k, g[k]) // 依据：论文 §7.4 的 Agga 定义；不存在的键由 a 映射为零元 ∅

因此最终聚合层的内部次序是：每组 aSUM → makeset → Agga 合并，每一层都已明确展开。

6. 用同一快照逐层手算

6.1 Filter：ℤ[Order] → ℤ[Order]

F(X) = {B(East,20)↦1, C(West,30)↦1, D(East,25)↦1} // 依据：A 的 amount=10 不满足谓词；其余记录满足，权重不变

6.2 Project：ℤ[Order] → ℤ[Pair]

P(F(X)) = {(East,20)↦1, (West,30)↦1, (East,25)↦1} // 依据：P 只保留 region 与 amount，并把输入权重带到输出

6.3 Grouping：ℤ[Pair] → ℤ[Pair][Region]

g = Gp(P(F(X))) g[East] = {(East,20)↦1, (East,25)↦1} // 依据：两条记录的 p 值都是 East g[West] = {(West,30)↦1} // 依据：该记录的 p 值是 West

6.4 每组 aSUM 与 makeset

aSUM(g[East]) = 20×1 + 25×1 = 45 // 第一个等号：aSUM 的加权和定义；第二个等号：整数运算 a(East,g[East]) = makeset((East,45)) = {(East,45)↦1} // 第一个等号：每组函数 a 的定义；第二个等号：makeset 的定义 aSUM(g[West]) = 30×1 = 30 // 第一个等号：aSUM 的定义；第二个等号：整数运算 a(West,g[West]) = makeset((West,30)) = {(West,30)↦1} // 依据依次为 a 与 makeset 的定义

6.5 Agga：ℤ[Pair][Region] → ℤ[Result]

Q(X) = Agga(g) // 依据：Q 的复合定义以及 g = Gp(P(F(X))) = a(East,g[East]) + a(West,g[West]) // 依据：Agga 对各 grouping 求和的定义 = {(East,45)↦1, (West,30)↦1} // 依据：Z-set 加法合并两个不同的完整结果记录
验证：电路结果 Q(X) 与第 2 节直接按 SQL 语义得到的 V 相同。

7. 完整快照电路与每条边

X ∈ ℤ[Order] │ ▼ F F(X) ∈ ℤ[Order] │ ▼ P P(F(X)) ∈ ℤ[Pair] │ ▼ Gp g ∈ ℤ[Pair][Region] │ 每个键 k 读取 g[k] ∈ ℤ[Pair] ▼ Agga，其中 a = makeset ∘ (k,aSUM) Q(X) ∈ ℤ[Result]

SQL 文本由此变成了可组合、可检查类型的快照电路 Q。每条边的对象以及每个节点的责任都已确定。

8. 边界：本课电路保留 SQL bag 语义

  • map/project 不隐式去重。若两条订单都映射为同一个完整 (region,amount)，输出 Z-set 中该记录的权重相加。
  • 权重属于完整记录。region 相同但 amount 不同的 (East,20) 与 (East,25) 是两个元素，不会只因分组键相同就合并为一条记录。
  • 本查询没有显式 DISTINCT。因此电路中不额外插入 distinct 节点；GROUP BY 最终每个非空组产生一条结果行来自每组 makeset，不是 project 自动去重。这与第 4 节 Table 1 的集合语义约定不同：Table 1 在投影／并／差末尾挂 distinct 是为了输出集合；本课示例按 SQL bag 语义保留多重性。
  • 本课结论只描述完整快照。这里没有输入变化、删除传播、跨批状态或端到端增量化。

9. 小结

  1. SQL 必须先变成有类型的 Z-set 快照电路，才能参与后续代数变换。
  2. 论文 Table 1 给出集合算子到 Z-set 电路的翻译；投影／并／差末尾挂 distinct，intersection 是全列 equi-join，difference 为 distinct(R − S)。
  3. 本查询保留 bag 语义，电路是 Q = Agga ∘ Gp ∘ P ∘ F，不在 P 后插入 distinct。
  4. Gp 产生 indexed Z-set，每个 region 键对应一个组内子 Z-set。
  5. 聚合层已展开为每组 aSUM、makeset 与 Agga，没有使用黑盒宏。
  6. 逐层手算得到 East45、West30，与直接 SQL 结果一致。
