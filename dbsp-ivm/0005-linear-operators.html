线性算子：为什么可以直接处理变化

教程制作 · 李金懋（OceanBase）

本课说明：有些快照算子满足“先合并两批 Z-set 再计算，等于分别计算后再把结果相加”。对这类算子，视图的本批变化可以只由输入的本批变化计算，不必先恢复完整快照。

依据：DBSP 论文 §2.2（Definition 2.14）与 §3（Theorem 3.3）

1. 问题：视图变化能否只看本批变化？

设 O 是作用于单个 Z-set 快照的算子。数据库在第 t 次变化前后的关系为：

Xt = Xt−1 + dt

这里 Xt−1 是旧快照，dt 是本批输入变化，Xt 是新快照。令新旧视图及其变化分别为：

Vt−1 = O(Xt−1) Vt = O(Xt) ΔVt = Vt − Vt−1

朴素做法先构造 Xt、计算 Vt，最后得到视图变化 ΔVt。先看一次具体的 filter 更新。

例：更新穿过 filter 的两个方向

令 O = filter(amount ≥ 20)。在第 4 个时刻，A 的金额从 10 更新为 25（向上穿过阈值，进入视图）；在第 5 个时刻，A 又从 25 更新为 15（向下穿过阈值，离开视图）。在 Z-set 中，UPDATE 表示为“删除旧行 + 插入新行”。以下以时刻为列，观察基表、视图及两种变化计算的结果。

对象t = 3（更新前）t = 4（A 进入视图）t = 5（A 离开视图）
基表快照X3 = {A10↦1, C30↦1}X4 = {A25↦1, C30↦1}X5 = {A15↦1, C30↦1}
基表增量—d4 = {A10↦−1, A25↦1}d5 = {A25↦−1, A15↦1}
视图快照V3 = O(X3) = {C30↦1}V4 = O(X4) = {A25↦1, C30↦1}V5 = O(X5) = {C30↦1}
视图增量—ΔV4 = V4 − V3 = {A25↦1}ΔV5 = V5 − V4 = {A25↦−1}
直接处理基表增量—O(d4) = filter({A10↦−1, A25↦1}) = {A25↦1}O(d5) = filter({A25↦−1, A15↦1}) = {A25↦−1}
两个方向结论一致：ΔV4 = O(d4)（A 进入视图，得到 +A25），ΔV5 = O(d5)（A 离开视图，得到 −A25）。按新旧视图相减得到的视图变化，恰好等于直接对基表变化运行 O 的结果。现在才提出要证明的一般结论：
快照层要证明的结论： ΔVt = O(dt) 流算子的朴素增量定义： (↑O)Δ = 𝒟 ∘ ↑O ∘ ℐ 对线性算子要证明的化简结果： (↑O)Δ = ↑O

朴素定义需要先用 ℐ 把变化流恢复为快照流，再逐时刻执行 O，最后用 𝒟 得到视图变化流。本课要证明：当 O 线性时，这三个步骤的结果等于直接对变化流逐时刻执行 O。

接下来的问题是：为什么 filter 可以把旧快照和本批变化分开处理，并让这个等式对任意时刻都成立？

2. 关键条件：线性

本课所需的线性条件是：对任意两个 Z-set A 和 B，

O(A + B) = O(A) + O(B)

这个等式允许把“旧快照”和“本批变化”分开处理：

O(Xt−1 + dt) = O(Xt−1) + O(dt)

随后，旧快照对应的输出可以在新旧视图之差中抵消。这正是直接计算变化所需的性质。

3. 推导：旧状态如何消失

从视图变化的定义开始：

ΔVt = Vt − Vt−1 // 视图变化的定义 = O(Xt) − O(Xt−1) // 新旧视图的定义 = O(Xt−1 + dt) − O(Xt−1) // Xt = Xt−1 + dt = [O(Xt−1) + O(dt)] − O(Xt−1) // 线性：O(A + B) = O(A) + O(B) = O(dt) // 同一个旧视图项一正一负，彼此抵消
线性真正做的事：它把 O(Xt−1 + dt) 展开为“旧快照的输出 + 本批变化的输出”。只有这样，旧输出才能在减去 Vt−1 时显式抵消。结论不是不执行 O，而是不必为了得到 ΔVt 重新执行 O(Xt)。

4. 把逐时刻结论写成流算子等式

令 d 是任意变化流。朴素增量算子定义为：

(↑O)Δ = 𝒟 ∘ ↑O ∘ ℐ

令 s = ℐ(d)，即 s 是由变化流 d 积分得到的快照流。再令 y = ↑O(s)，即 y 是对快照流逐时刻执行 O 得到的视图快照流。因此，对任意逻辑时刻 t：

(↑O)Δ(d)[t] = (𝒟 ∘ ↑O ∘ ℐ)(d)[t] // 代入朴素增量定义 = 𝒟(y)[t] // s = ℐ(d)，y = ↑O(s) = y[t] − y[t−1] // 𝒟 的定义：当前项减去前一项 = O(s[t]) − O(s[t−1]) // y = ↑O(s)，所以 y[t] = O(s[t])，y[t−1] = O(s[t−1]) = O(d[t]) // s[t] = s[t−1] + d[t]，使用第 3 节的线性推导 = (↑O)(d)[t] // ↑O 的定义

这对任意逻辑时刻 t 都成立，所以两条输出流的每一项相同：

(↑O)Δ = ↑O
右侧必须写 ↑O，不能只写 O：左、右两边都是以流为输入、以流为输出的算子；O 的输入和输出则是单个快照。

5. 哪些算子可以直接处理变化？

filter

对每条记录，要么保留原来的整数权重，要么把权重变为 0。因此对 Z-set 加法保持不变，是线性的。

map / project

记录映射到输出 key 后，落在同一个 key 的权重仍按整数相加。因此即使多个输入记录映射到同一输出记录，仍保持加法。

例如查询 SELECT id FROM orders WHERE amount >= 20 可由 filter 和 project 组成。二者都线性时，输入变化可按原有算子顺序经过这两个算子。

边界：distinct 不满足线性：A = B = {a↦1} 时 distinct(A+B) = {a↦1} ≠ distinct(A)+distinct(B) = {a↦2}。join 是二元算子，不属于本课一元线性范畴，不能直接套 (↑O)Δ = ↑O。

6. 小结

Xt = Xt−1 + dt ↓ 线性：O(Xt−1 + dt) = O(Xt−1) + O(dt) ↓ Vt − Vt−1 中的 O(Xt−1) 抵消 ↓ ΔVt = O(dt) ↓ (↑O)Δ = ↑O

线性算子的增量实现只处理本批变化；它不需要先重建完整快照再运行同一个算子。
