朴素增量与链式法则：从整体定义到基础算子

教程制作 · 李金懋（OceanBase）

本课从完整定义推导查询的增量算子，并证明复合查询可以按链式法则拆成逐算子增量。链式法则只给出语义分解；效率要靠后续为各算子改写出高效增量实现。

依据： DBSP §3–§4：增量化与 DBSP 算子 · arXiv:2203.16684

1. 朴素增量：先定义正确的输出

对快照查询 Q，输入是数据库变化流 ΔDB，目标是输出视图变化流 ΔV。先把 Q 变为流算子 ↑Q，其朴素增量定义为：

(↑Q)Δ = 𝒟 ∘ ↑Q ∘ ℐ
ΔDB→ ℐ→ 数据库快照流→ ↑Q→ 视图快照流→ 𝒟→ ΔV
  • ℐ：把输入变化累加为数据库快照流。
  • ↑Q：在每个时刻对该时刻的完整数据库快照执行 Q。
  • 𝒟：把相邻视图快照之差作为输出变化。
它为什么正确？由定义，(↑Q)Δ(ΔDB) 就是完整视图快照流 ↑Q(ℐ(ΔDB)) 的相邻差。因此，它精确规定了任何增量实现应当输出什么。
它为什么不能直接执行？ℐ 会恢复完整数据库快照，↑Q 仍在完整快照上执行原查询。变化再小，也可能需要重跑全量查询。朴素增量在这里的作用不是提供高效算法，而是定义高效实现必须产生的结果。

2. 链式法则：把整体定义拆到基础算子

复合查询写作：

Q = Q₁ ∘ Q₂ // 数据流：输入 ──→ Q₂ ──→ Q₁ ──→ 输出
输入→ Q₂→ Q₁→ 输出

2.1 不分解时缺少什么

直接套朴素定义，只得到整条查询的定义：

(↑(Q₁ ∘ Q₂))Δ = 𝒟 ∘ ↑(Q₁ ∘ Q₂) ∘ ℐ

这个式子把 Q₁ ∘ Q₂ 当成黑盒：它没有给出“Q₂ 的输出变化如何作为 Q₁ 的输入变化”。因此无法把整体正确性要求分配给两个基础算子，也无法分别替换它们的实现。

2.2 从整体定义推导

只用两件已知事实：

  • ↑(Q₁ ∘ Q₂) = ↑Q₁ ∘ ↑Q₂：Lift 保持函数复合。
  • 对任意快照流 s，ℐ(𝒟(s)) = s：先差分再积分会还原该快照流。
(↑(Q₁ ∘ Q₂))Δ = 𝒟 ∘ ↑(Q₁ ∘ Q₂) ∘ ℐ // 朴素增量定义 = 𝒟 ∘ ↑Q₁ ∘ ↑Q₂ ∘ ℐ // Lift 保复合 = 𝒟 ∘ ↑Q₁ ∘ (ℐ ∘ 𝒟) ∘ ↑Q₂ ∘ ℐ // 中间快照流先差分再积分，不变 = (𝒟 ∘ ↑Q₁ ∘ ℐ) ∘ (𝒟 ∘ ↑Q₂ ∘ ℐ) // 重新结合括号 = (↑Q₁)Δ ∘ (↑Q₂)Δ // 认出两段的朴素增量定义

2.3 结论与作用

(↑(Q₁ ∘ Q₂))Δ = (↑Q₁)Δ ∘ (↑Q₂)Δ

右边形成明确接口：

ΔDB→ (↑Q₂)Δ→ 中间变化流→ (↑Q₁)Δ→ ΔV
链式法则解决什么？把整体输出定义拆到各基础算子，并保证局部增量算子按原顺序连接后仍产生同一整体结果；之后才能逐算子做高效实现。
链式法则不解决什么？它不自动减少计算量，也不消除状态。若每个 (↑Qᵢ)Δ 仍按朴素定义执行，管道仍可能慢；真正的效率来自每个基础算子的具体高效实现。

3. 小结

  • (↑Q)Δ = 𝒟∘↑Q∘ℐ 定义增量计算应产生的结果：输出应等于完整视图的相邻差。
  • 整体问题：复合查询的整体定义把内部算子当黑盒，不能分别替换局部实现。
  • 链式法则：用 Lift 保复合与 ℐ(𝒟(s))=s，把整体定义拆成逐算子的定义。
  • 效率来源：各基础算子的高效增量实现，而不是链式分解本身。
还差的一步：链式法则已经把朴素增量拆成逐算子的形式；但如果每个 (↑Qᵢ)Δ 仍按 𝒟∘↑Qᵢ∘ℐ 执行，就仍要先积分得到快照、执行快照算子、再差分输出，计算依然可能很慢。效率要由各个基础算子的具体增量等式来获得。
