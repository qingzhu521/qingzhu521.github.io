快照电路的机械增量化

教程制作 · 李金懋（OceanBase）

本课严格沿 Algorithm 4.8，把一条有类型的 SQL 快照电路转换成处理变化流的电路，并用一个事务验证局部高效实现与全量重算产生相同结果。

依据：DBSP 论文 §4.3 Algorithm 4.8，以及 §7.2–§7.4 对聚合、分组与分组聚合增量性的说明。

1. 问题：运行时收到变化，Q 却读取完整快照

快照查询仍是：

SELECT region, SUM(amount) AS total FROM orders WHERE amount >= 20 GROUP BY region;

它已翻译成类型为 Q : ℤ[Order] → ℤ[Result] 的快照电路：

Q = Agga ∘ Gp ∘ P ∘ F F : ℤ[Order] → ℤ[Order] P : ℤ[Order] → ℤ[Pair] Gp : ℤ[Pair] → ℤ[Pair][Region] Agga : ℤ[Pair][Region] → ℤ[Result] a(k,s) = ∅ 若 aCOUNT(s)=0 makeset((k,aSUM(s))) 若 aCOUNT(s)>0

运行时输入不是每批复制一遍完整 orders，而是一条变化流 d。若每批先恢复完整表，再对所有订单运行 F、P、Gp 和所有分组聚合，计算量取决于完整数据库及全部分组，而不只取决于本批变化。

2. Algorithm 4.8 的五个机械步骤

论文给出的增量视图维护算法按以下顺序处理查询：

  1. 翻译查询。把关系查询 Q 翻译成 Z-set 快照电路。本例就是上一节列出的 F → P → Gp → 每组 aSUM → makeset/Agga。
  2. 合并 distinct（distinct consolidation）。 定义：在 Z-set 电路上反复重写，合并相邻的 distinct，或把可被算子吸收／推迟的 distinct 删掉或后移，直到不能再应用为止（论文 Algorithm 4.8 第 2 步：until convergence）。 动机：上一课 §4 已说明，论文 Table 1 在投影、并、差等集合语义算子末尾挂 distinct，以把多重集压回集合；直接翻译会在电路中留下一串冗余 distinct。每个 distinct 在增量电路里都要对照旧权重（第 7 课的 H）并占用状态，因此编译器必须合并。 合法性依据（论文 §4.2）：
    • Proposition 4.5：若 Q 是 filter σ、join ⋈ 或笛卡尔积 ×，且输入 i 满足 ispositive(i)，则 Q(distinct(i)) = distinct(Q(i))。该式允许把 distinct 推迟到 Q 之后（delay the application of distinct）。
    • Proposition 4.6：若 Q 是 filter σ、投影 π、selection（map）、加法 +、join 或 ×，且 ispositive(i)，则 distinct(Q(distinct(i))) = distinct(Q(i))。由此可在一串计算末尾只保留一个 distinct（consolidate … by performing one distinct at the end of a chain）。
    本课固定 SQL 没有显式 DISTINCT，且按 bag 语义也不在 project 后去重，因此本例没有 distinct 节点需要合并；带集合语义的端到端 consolidation 见下一节论文 §4.4 例子。
  3. Lift 整条电路。由快照算子 Q 定义流算子 ↑Q。
  4. 构造朴素增量。用 ℐ 与 𝒟 包围 ↑Q，得到 (↑Q)Δ。
  5. 递归化简。应用增量算子的链式法则和各基础算子的性质，把整条朴素增量分解到局部，再替换为高效局部实现。

前四步定义输出必须是什么；第五步才改写内部计算，使它尽可能直接处理变化。

3. 从 Q 到 ↑Q，再到朴素增量

3.1 Lift 后的快照流电路

↑Q 的类型是从订单快照流到结果快照流。对任意逻辑时刻 t：

(↑Q)(s)[t] = Q(s[t]) // 依据：Lift 的定义

左侧在时刻 t 只读取输入快照流的当前项 s[t]；不会读取其他时刻。

3.2 用 ℐ 与 𝒟 构造朴素增量

(↑Q)Δ = 𝒟 ∘ ↑Q ∘ ℐ // 依据：流算子的朴素增量定义

给定订单变化流 d，先命名两条中间流：

s = ℐ(d) // s 是完整订单快照流 y = ↑Q(s) // y 是完整查询结果快照流

对任意逻辑时刻 t，s[t] 读取并累加 d[0] 到 d[t]；y[t] 只读取同一时刻的 s[t]；𝒟(y)[t] 读取 y[t] 与前一项 y[t−1]（初始时刻以前取零元）。于是：

(↑Q)Δ(d)[t] = 𝒟(y)[t] // 依据：(↑Q)Δ 的定义以及 s、y 的命名 = y[t] − y[t−1] // 依据：𝒟 的定义 = Q(s[t]) − Q(s[t−1]) // 依据：y = ↑Q(s) 与 Lift 的定义

这条等式定义高效实现必须产生的结果：新完整查询结果减去旧完整查询结果。但按这个形式直接执行，仍会在两张完整快照上运行 Q。

4. 链式法则建立局部边界，局部规则带来效率

对普通可复合快照算子，链式法则把整体朴素增量分解为各段朴素增量。例如电路前半段满足：

(↑(Gp ∘ P ∘ F))Δ = (↑Gp)Δ ∘ (↑P)Δ ∘ (↑F)Δ // 依据：增量算子的链式法则，递归应用于复合结构

链式法则保证各局部增量实现连接后仍满足整条 (↑Q)Δ 的输出定义；它本身没有消除局部定义里的积分、完整快照执行与差分。效率来自继续应用以下局部规则：

层局部结论实际效果
filter F(↑F)Δ = ↑FF 线性，直接过滤本批带权重记录
project P(↑P)Δ = ↑PP 线性，直接映射本批记录并保留权重
grouping Gp(↑Gp)Δ = ↑GpGp 线性，只把本批变化送入对应键的 grouping
每组 aSUM(↑aSUM)Δ = ↑aSUMaSUM 线性，用本批加权金额更新组内标量
makeset(↑makeset)Δ = 𝒟 ∘ ↑makeset ∘ ℐ不线性；读取该组新旧标量，撤回旧结果行并插入新结果行
论文边界：Gp 与 aSUM 线性，makeset 不线性。论文 §7.4 对分组聚合给出的效率结论是：输入 grouping 发生变化时，只需重新计算发生变化的 grouping。这里不把整个 GROUP BY 聚合虚构成一个全局线性算子。

5. 论文 §4.4 的完整例子：电路如何一步步变成增量版

本课主线 SQL 是 bag 语义的分组聚合，电路里没有 distinct。论文 §4.4 另给了一条带 DISTINCT 与 join 的集合查询，正好把 Algorithm 4.8 五步连同 Figure 1 的电路演化走完一遍。查询为：

CREATE VIEW v AS SELECT DISTINCT t1.x, t2.y FROM ( SELECT t1.x, t1.id FROM t WHERE t.a > 2 ) t1 JOIN ( SELECT t2.id, t2.y FROM r WHERE r.s > 5 ) t2 ON t1.id = t2.id

5.1 原查询 t ──→ σa>2 ──→ distinct ──→ πx,id ──→ distinct ──┐ ⋈id ──→ πx,y ──→ distinct ──→ V r ──→ σs>5 ──→ distinct ──→ πy,id ──→ distinct ──┘ 5.2 consolidation（Prop. 4.6 → 4.5 → 4.6） t ──→ σa>2 ──→ πx,id ──┐ ⋈id ──→ πx,y ──→ distinct ──→ V r ──→ σs>5 ──→ πy,id ──┘ 5.3 Lift t ──→ ↑σa>2 ──→ ↑πx,id ──┐ ↑⋈id ──→ ↑πx,y ──→ ↑distinct ──→ V r ──→ ↑σs>5 ──→ ↑πy,id ──┘ 5.4 朴素增量 Δt ──→ ℐ ──→ ↑σa>2 ──→ ↑πx,id ──┐ ↑⋈id ──→ ↑πx,y ──→ ↑distinct ──→ 𝒟 ──→ ΔV Δr ──→ ℐ ──→ ↑σs>5 ──→ ↑πy,id ──┘ 5.5 链式展开 Δt ──→ (↑σa>2)Δ ──→ (↑πx,id)Δ ──┐ (↑⋈id)Δ ──→ (↑πx,y)Δ ──→ (↑distinct)Δ ──→ ΔV Δr ──→ (↑σs>5)Δ ──→ (↑πy,id)Δ ──┘ 5.6 最终（见上图 / Figure 1）

5.1 原查询电路（Algorithm 4.8 第 1 步：Table 1 翻译）

集合语义下，filter／project 末尾各挂 distinct，join 后再 project，输出再 distinct：

t ──→ σa>2 ──→ distinct ──→ πx,id ──→ distinct ──┐ ⋈id ──→ πx,y ──→ distinct ──→ V r ──→ σs>5 ──→ distinct ──→ πy,id ──→ distinct ──┘

用了哪条规则：Algorithm 4.8 第 1 步 + 上一课 Table 1「集合语义算子末尾挂 distinct」。

5.2 distinct consolidation（Algorithm 4.8 第 2 步）

先用 Proposition 4.6 去掉各支路上「算子前后成对」的冗余 distinct，得到：

t ──→ σa>2 ──→ πx,id ──→ distinct ──┐ ⋈id ──→ πx,y ──→ distinct ──→ V r ──→ σs>5 ──→ πy,id ──→ distinct ──┘

再用 Proposition 4.5 把 join 两侧的 distinct 推迟到 join 之后：

t ──→ σa>2 ──→ πx,id ──┐ ⋈id ──→ distinct ──→ πx,y ──→ distinct ──→ V r ──→ σs>5 ──→ πy,id ──┘

再应用一次 Proposition 4.6，把末尾链上的两个 distinct 合并为一个：

t ──→ σa>2 ──→ πx,id ──┐ ⋈id ──→ πx,y ──→ distinct ──→ V r ──→ σs>5 ──→ πy,id ──┘

用了哪条规则：Algorithm 4.8 第 2 步；合法重写依据是 Prop. 4.5（推迟）与 Prop. 4.6（链末只留一个 distinct）。

5.3 Lift 整条电路（Algorithm 4.8 第 3 步）

t ──→ ↑σa>2 ──→ ↑πx,id ──┐ ↑⋈id ──→ ↑πx,y ──→ ↑distinct ──→ V r ──→ ↑σs>5 ──→ ↑πy,id ──┘

用了哪条规则：Algorithm 4.8 第 3 步（Lift；复合对 Lift 分配）。此时输入／输出已是完整快照流。

5.4 套朴素增量 ℐ / 𝒟（Algorithm 4.8 第 4 步）

Δt ──→ ℐ ──→ ↑σa>2 ──→ ↑πx,id ──┐ ↑⋈id ──→ ↑πx,y ──→ ↑distinct ──→ 𝒟 ──→ ΔV Δr ──→ ℐ ──→ ↑σs>5 ──→ ↑πy,id ──┘

用了哪条规则：Algorithm 4.8 第 4 步，即 (↑Q)Δ = 𝒟 ∘ ↑Q ∘ ℐ。语义正确，但内部仍在完整快照上算。

5.5 链式法则展开（Algorithm 4.8 第 5 步 · 分解）

Δt ──→ (↑σa>2)Δ ──→ (↑πx,id)Δ ──┐ (↑⋈id)Δ ──→ (↑πx,y)Δ ──→ (↑distinct)Δ ──→ ΔV Δr ──→ (↑σs>5)Δ ──→ (↑πy,id)Δ ──┘

用了哪条规则：Algorithm 4.8 第 5 步中的链式法则（本课第 4 节）。

5.6 局部规则替换 → 最终增量电路（Algorithm 4.8 第 5 步 · 化简）

先用线性：(↑σ)Δ = ↑σ、(↑π)Δ = ↑π：

Δt ──→ ↑σa>2 ──→ ↑πx,id ──┐ (↑⋈id)Δ ──→ ↑πx,y ──→ (↑distinct)Δ ──→ ΔV Δr ──→ ↑σs>5 ──→ ↑πy,id ──┘

再把 (↑⋈)Δ 换成双线性三项（两侧各带 ℐ／z⁻¹ 读旧状态），把 (↑distinct)Δ 换成带 ℐ／z⁻¹ 与 ↑H 的电路，即论文 Figure 1：

对照本课主线：本例无 join／distinct 节点，化简停在各线性算子与 makeset 的局部差；§4.4 额外展示 distinct consolidation 收成一个，以及 join／distinct 各自带上持久状态。

6. 一个事务逐层执行

事务开始前沿用固定完整快照：

Xold = {A(East,10)↦1, B(East,20)↦1, C(West,30)↦1, D(East,25)↦1} Q(Xold) = {(East,45)↦1, (West,30)↦1}

本批删除 B(East,20)，插入 E(East,35)：

dt = {B(East,20)↦−1, E(East,35)↦1}

6.1 Filter：两条变化都通过

F(dt) = {B(East,20)↦−1, E(East,35)↦1} // 依据：20 与 35 都满足 amount ≥ 20，F 保留各自权重

6.2 Project：得到同一个 East 键下的金额变化

P(F(dt)) = {(East,20)↦−1, (East,35)↦1} // 依据：P 映射记录形状，权重 −1 与 +1 不变

6.3 Grouping：只有 East grouping 变化

Gp(P(F(dt)))[East] = {(East,20)↦−1, (East,35)↦1} // 依据：两条 Pair 的分组键都是 East Gp(P(F(dt)))[West] = ∅ // 依据：本批没有 West 记录

因此无需重新计算 West grouping。

6.4 aSUM：更新 East 内部标量

Δsum[East] = 20×(−1) + 35×(+1) // 依据：aSUM 的加权和定义 = +15 // 依据：整数运算 sumnew[East] = sumold[East] + Δsum[East] // 依据：aSUM 的线性 = 45 + 15 = 60 // 依据：旧状态与整数运算

同批 Δcount=(−1)+(+1)=0，所以 East 组仍存在。+15 是内部标量变化，不是 SQL 输出行。

6.5 makeset：构造新旧结果行之差

outold[East] = makeset((East,45)) = {(East,45)↦1} // 依据：旧总和与 makeset 定义 outnew[East] = makeset((East,60)) = {(East,60)↦1} // 依据：新总和与 makeset 定义 ΔVt[East] = outnew[East] − outold[East] // 依据：朴素增量要求的新结果减旧结果 = −(East,45) + (East,60) // 依据：Z-set 减法
不能输出 +(East,15)。它会新增一条 total=15 的结果行，却不会撤回旧的 total=45。内部 Δsum=+15 与外部关系变化 −(East,45)+(East,60) 是不同类型的对象。

7. 用全量重算验证增量结果

应用事务后：

Xnew = Xold + dt = {A(East,10)↦1, C(West,30)↦1, D(East,25)↦1, E(East,35)↦1} // 依据：删除 B 的 −1 与原权重 +1 抵消，再加入 E

全量执行原 SQL：A10 被过滤；East 为 D25+E35=60，West 仍为 C30。

Q(Xnew) = {(East,60)↦1, (West,30)↦1} // 依据：对新完整快照执行原 SQL Q(Xnew) − Q(Xold) = {(East,60)↦1, (West,30)↦1} − {(East,45)↦1, (West,30)↦1} // 依据：输出增量定义 = −(East,45) + (East,60) // 依据：相同的 West30 权重 +1 与 −1 抵消
全量验证得到的输出变化与逐层高效实现完全一致。

8. 朴素形式与高效形式对照

朴素形式

(↑Q)Δ = 𝒟 ∘ ↑Q ∘ ℐ

  1. 把变化流积分成完整订单快照。
  2. 每批对完整快照运行整个 Q。
  3. 对相邻完整结果做差。

价值：定义任何实现都必须产生的正确输出。

高效形式

  1. F、P、Gp 直接处理本批变化。
  2. 只更新本批变化涉及的 East grouping。
  3. aSUM 线性更新 45+15=60。
  4. makeset 局部产生 −East45+East60。

价值：在保持相同输出的前提下，跳过未变化记录和未变化 grouping。

链式法则负责把整体结果定义连接到局部边界；实际减少工作量的是 filter、project、grouping、aSUM 的线性化简与 makeset 的局部增量实现。

9. 边界：组创建与组消失

本例是“组持续存在、总和改变”。另外两种情况仍由每个受影响 grouping 的 outnew−outold 统一处理：

旧 count新 count该组输出变化
0> 0+(g,sumnew)
> 00−(g,sumold)
> 0> 0−(g,sumold)+(g,sumnew)

COUNT 用于判断 grouping 是否存在，不能只用 sum 判断，因为非空组的总和也可能恰为 0。本课 SQL 没有显式 distinct，因此没有额外的 distinct 增量状态。

10. 效率从哪来：论文 §4.5 复杂度对照

记 C[t] = ‖s[t]‖ 为本批变化流在时刻 t 的规模，R[t] = ‖ℐ(s)[t]‖ 为积分后完整关系的规模。未化简的朴素增量 𝒟 ∘ ↑Q ∘ ℐ 在完整关系上求值，时间是 R[t] 的函数，并因 ℐ／𝒟 使用 O(R[t]) 内存。§3 的局部化简把多数算子的时间压到 C[t] 的函数；在 C[t] ≪ R[t] 时带来实质加速。论文 §4.5 对各算子类别的结论如下：

算子类别每批时间复杂度持久状态对应课程
线性算子（filter、project、grouping、aSUM 等） O(C[t]) 0 0005：零状态，直接处理本批变化
双线性算子（join、笛卡尔积） O(C[t]²) O(R[t]) 0006：两侧旧状态 + 三项公式
distinct（经 H 实现） O(C[t]) O(R[t]) 0007：按键维护 multiplicity／H
分组聚合中的非线性层（makeset／emit） 与变化涉及的 grouping 规模成比例 按组保存 count／sum 等 0008：按组状态；只重算变化的 grouping

出处：DBSP 论文 §4.5（线性 Theorem 3.3；双线性 Theorem 3.4；distinct Proposition 4.7）；分组聚合效率边界见 §7.4。表中 ℐ 本身虽占 O(R[t]) 内存，求值时间仍为 O(C[t])（本批输出中的值必出现在本批输入变化中）。

增量化成本不均摊。线性算子不保留持久状态；join 与 distinct 需要 O(R[t]) 状态。状态需求全部来自非线性（及双线性）算子——不是「整条查询平均摊一点状态」，而是哪些节点打破了「只看本批变化」决定了内存画像。

11. 小结

  1. Algorithm 4.8 的路径是：查询翻译 → distinct consolidation → Lift → 𝒟 ∘ ↑Q ∘ ℐ → 链式分解与局部化简。
  2. distinct consolidation 依据 Prop. 4.5（可推迟）与 Prop. 4.6（链末只留一个），消除 Table 1 翻译带来的冗余 distinct。
  3. (↑Q)Δ = 𝒟 ∘ ↑Q ∘ ℐ 定义正确输出，但直接执行会恢复完整快照并重跑 Q。
  4. 链式法则提供分解与正确性连接；效率来自各基础算子的增量规则。
  5. 论文 §4.4 例子把集合查询从「多 distinct 快照电路」经 consolidation、Lift、朴素增量、链式展开，化到 Figure 1 的 join／distinct 状态电路。
  6. F、P、Gp、aSUM 线性；makeset 不线性，只对变化的 grouping 构造新旧结果行之差。
  7. 本批 East 内部总和变化是 +15，最终关系变化是 −(East,45)+(East,60)。
  8. §4.5：线性 O(C[t])／零状态；join O(C[t]²)／O(R[t]) 状态；distinct O(C[t])／O(R[t]) 状态。状态全部来自非（双）线性算子。
